# TOC One-Shot 工具細節參考

本檔案是 toc-one-shot skill 的背景參考。**只在遇到工具細節不確定時才 Read 進來**，不要在對話輸出中引用。

資料來源：基於 Eliyahu M. Goldratt 的限制理論（TOC）著作與後續學術／實務文獻濃縮而成。

---

## 1. TOC 的兩個系統

TOC 在歷史上有兩條發展線，被本 skill 的六個動詞涵蓋如下：

**Operations 線（1984+，《The Goal》）**——處理物理流量受限的系統。核心是五步驟，對應動詞一。

**Thinking Processes 線（1994+，《It's Not Luck》）**——處理邏輯打結的系統。核心是五棵樹，對應動詞二到六。

兩條線在實務上經常需要混用（物理瓶頸的背後常常有政策衝突在撐著）。

---

## 2. 五步驟（對應動詞一）

完整流程：

1. **Identify** the system's constraint（找出系統的約束）
2. **Exploit** the constraint（充分利用約束——一秒都不浪費它）
3. **Subordinate** everything else to the constraint（其他環節配合它，不要追求局部效率）
4. **Elevate** the constraint（提升約束——擴產能、加機器、加人手）
5. **Repeat**（瓶頸轉移後，回到第一步）

**為什麼順序重要**：第二步（充分利用現有瓶頸）通常能解放 20-30% 的隱形產能，**完全不花錢**。直接跳到第四步（擴產能）是最常見的錯誤——用錢解決可以用方法解決的問題。

**Subordinate 的反直覺**：非瓶頸環節**不應該追求 100% 利用率**。它們應該以瓶頸的速度跑，否則會在瓶頸前堆積大量在製品（WIP），實際上拖慢整個系統。這違反傳統管理會計直覺。

**配套工具**：DBR（Drum-Buffer-Rope）排程、Buffer Management、Throughput Accounting、Critical Chain Project Management。

## 3. 五棵樹的精確對應

| 樹 | 英文 | 對應動詞 | 使用的邏輯 | 核心產出 |
|:---|:---|:---|:---|:---|
| 現況樹 | Current Reality Tree (CRT) | 動詞二 | 充分條件 | 核心問題 / 核心衝突 |
| 衝突化解圖（蒸發雲） | Evaporating Cloud (EC) | 動詞三 | 必要條件 | 注入點 Injection |
| 未來樹 | Future Reality Tree (FRT) | 動詞四 | 充分條件 + NBR | DEs + 副作用防線 |
| 條件樹 | Prerequisite Tree (PRT) | 動詞五 | 必要條件 | 中期目標 IOs 序列 |
| 轉型樹 | Transition Tree (TT) | 動詞六 | 充分條件 | 具體動作步驟 |

S&T Tree（策略與戰術樹）是後期發展，用於跨層級組織對齊，本 skill 不處理。

## 4. CLR 合法保留類別（七條文法）

每次畫出一條「因為 A 所以 B」的箭頭，都必須通過這七關：

1. **實體存在**：A 和 B 是否真實存在、清楚陳述？
2. **因果關係存在**：A 真的會導致 B 嗎，還是只是相關？
3. **原因不足**：A 夠不夠單獨引起 B？還是需要加上 A'？（最常見的漏洞）
4. **額外原因**：除了 A，還有沒有其他獨立的原因也能引起 B？
5. **因果倒置**：會不會其實是 B 導致 A？
6. **預期效應**：如果 A 真的導致 B，還應該觀察到什麼其他效應？觀察到了嗎？
7. **同義反覆**：A 與 B 是不是用不同字描述同一件事？

寫完現況樹、未來樹時，用這七條檢驗每一條箭頭。

## 5. 現況樹（CRT）的建法

1. **列 UDEs**（不良效應）：5–10 個能讓組織多數人同意「這就是不對勁」的現象。
   - 合格：「客訴回應平均耗時 48 小時」「工程師每週花 12 小時在不必要的會議」
   - 不合格：「公司氣氛差」「大家都不開心」（太抽象）

2. **兩兩連線**：找出 UDE 之間的因果關係。
   - A→B：A 是 B 的充分原因
   - A+C→B：A 和 C 一起才能引起 B（邏輯 AND，畫橢圓）

3. **往下追根**：每個 UDE 上游是什麼？追到沒有上游為止。

4. **收斂到核心問題**：通常 70% 以上的 UDEs 都可以追到 1–2 個根節點。

5. **核心問題通常長這樣**：
   - 一條過時的政策（「所有部門都要把設備利用率做到 95%」）
   - 一個未被檢驗的假設（「我們的客戶只在乎價格」）
   - 一個結構性衝突（「業務想接急單 vs 生產想要穩定排程」）

## 6. 蒸發雲（EC）的 A-B-C-D-D' 結構

```
          B (必要條件1) ──要求── D  (做法1)
         /                              \
共同目標 A                              衝突
         \                              /
          C (必要條件2) ──要求── D' (做法非1)
```

讀法：
- 為了達成 **A**，必須同時滿足 **B** 和 **C**
- 滿足 B 需要做 **D**；滿足 C 需要做 **D'**
- 但 **D 和 D' 彼此衝突**

**關鍵：衝突不在 D vs D'，衝突在 B→D 與 C→D' 兩條箭頭背後的隱藏假設。**

例：
- A = 公司永續賺錢
- B = 維持高品質 → D = 採購貴的高品質原料
- C = 維持低成本 → D' = 採購便宜的原料
- 表面衝突：貴 vs 便宜
- 真正衝突（隱藏假設）：「品質=原料價格」「成本=採購單價」——這兩個假設一旦被挑戰，衝突就蒸發

**找 Injection 的方法**：把 B→D、C→D'、B↔C、A→B、A→C 這五條箭頭背後的假設全部列出來（通常每條 2–3 個，共 10–15 個假設），逐一挑戰：「這個假設在什麼情況下不成立？」只要找到一個可以被反證的假設，衝突就能蒸發。

## 7. 未來樹（FRT）與 NBR

Injection 找到後，未來樹驗證它會不會真的解決問題：

1. **推論 DEs**（理想效應）：假設 Injection 已實施，會產生什麼好效應？
2. **對照 UDEs**：理想上每個 UDE 都能被某個 DE 消滅掉。有消不掉的，代表 Injection 不完整，需要補充第二個 Injection。
3. **做 NBR**（負面分支保留）：同一個 Injection 會不會長出壞分支？

NBR 標準寫法：
> 如果我們做 [Injection]，
> 會導致 [負面效應]，
> 因為 [隱藏的副作用邏輯]。
> 為了封堵，我們需要 [額外的 Injection 或配套措施]。

實踐者默契：**至少想出 3 條 NBR，封堵掉每一條。**

## 8. 條件樹（PRT）與轉型樹（TT）

**條件樹**解決「障礙排序」問題：

1. **列出障礙**：實施 Injection 會碰到什麼阻力？
2. **把每個障礙翻成中期目標**：
   - 障礙：「工程師拒絕改變工作流程」
   - IO：「工程師主動願意採用新流程」
3. **用必要條件排序**：為了達成 IO-B，必須先達成 IO-A 嗎？
4. **找出關鍵路徑**

**轉型樹**針對每個 IO，寫出：
- 現狀是什麼
- 我要做什麼動作
- 這個動作為什麼會讓現狀變成 IO
- 做完後狀態是什麼

轉型樹的每一行都要能被第一線執行者看懂並同意。

## 9. 變革管理的人性層（Six Layers of Resistance）

人對變革的抗拒有六層，必須逐層化解，跳層就會被反彈：

1. **不認為有問題**：用 CRT 讓人看到 UDEs（動詞二）
2. **不同意問題的定義**：用 CRT 追到核心問題（動詞二）
3. **不相信方案能解**：用 FRT 展示 DEs 如何消滅 UDEs（動詞四）
4. **擔心副作用**：用 NBR 先認領副作用、展示封堵（動詞四）
5. **覺得障礙太大**：用 PRT 把障礙拆成可解的 IOs（動詞五）
6. **實施過程的恐懼與未知**：用 TT 把每一步動作講清楚（動詞六）

這也是六個動詞要依序走、不可跳的深層理由：**跳層 = 輸在抗拒**。

## 10. 常見錯誤

- **UDE 太少或太抽象**：至少 5 個，每一個都要具體到可觀察
- **急著下結論是誰的錯**：TOC 追的是系統問題，不是追究個人
- **把妥協當突破**：「各退一步」不是 Injection，Injection 必須打破假設
- **沒做 NBR 就實施**：變革失敗率最高的原因
- **跳過動詞六直接下令**：再好的方案，執行層沒有具體動作就會爛掉
- **直接跳到 Elevate**：先做 Exploit 和 Subordinate，這兩步通常不花錢就解放 20-30% 產能
- **非瓶頸環節追求 100% 利用率**：會在瓶頸前堆積 WIP，實際上拖慢整個系統

## 11. 走完的檢查清單

- [ ] **動詞一**（如有用）：瓶頸環節明確指認、產出率數字、三件事清單（Exploit/Subordinate/Elevate）
- [ ] **動詞二**：至少 5 個具體 UDEs、因果鏈通過 CLR 前三條、收斂到單一核心問題
- [ ] **動詞三**：A-B-C-D-D' 完整、列出 5-10 個隱藏假設、指出哪一個被打破
- [ ] **動詞四**：DEs 對照 UDEs、至少 3 條 NBR 與封堵方案、Injection 完整性檢查
- [ ] **動詞五**：障礙清單涵蓋政治/認知/能力/資源/時間五類、IOs 序列、關鍵路徑
- [ ] **動詞六**：每個 IO 有具體動作、第一個七天的明確指令、可被第一線理解

少一項就退回那一動重做。

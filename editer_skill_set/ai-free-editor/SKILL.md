# AI-free Editor

審查中文文字的 AI 味，並提出具體改寫方向。

## 三個維度的定義

這三個維度是上游的生成器：所有 AI 文章的常見壞味——「她不是 X，她是 Y」對仗句、抽象金句堆疊、三段排比、概念名詞化、沒有時間地點人名——都可以用這三個維度的失能解釋。

### 錨

文字裡有沒有可以拍成電影的東西？

- **具體時間**：不是「某個午後」，而是「2019 年 12 月那個下午」「上禮拜三下午三點」
- **具體地點**：不是「在城市裡」「在那家咖啡店」，而是「台北車站三樓的星巴克」「松菸後面那條巷子」
- **具體人名**：不是「我朋友」「某人」「曾經有個人」，而是「我大學同學阿芳」「Linda」「我媽」
- **具體感官細節**：醬油在盤子邊乾了一圈、冰拿鐵、外套口袋掉出來的零錢、廚房燈管嗡嗡的聲音、皮膚被冷氣吹久了那種乾

**錨壞的訊號詞**：「在這個忙碌的城市裡」「某個午後」「曾經有個人告訴我」「在這個快節奏的時代」「某個朋友」「某種程度上」「我認識的一個人」

### 歪

句子節奏對稱還是不對稱？

- **對稱壞訊號**：「不是 X，而是 Y」、「不是 A，不是 B，而是 C」、三段排比、整齊對仗、相同長度的句子連續出現三次以上、「願妳○○、願妳○○、願妳○○」
- **不對稱好訊號**：句子長短跳動、突然停下來解釋一個詞、岔題又繞回來、單句忽然只有三個字

人寫東西是歪的。AI 寫東西像被熨斗燙過。

### 動

用動詞推進還是用名詞鋪面？

- **名詞化壞訊號**：「○○感」「○○性」「○○化」「對○○的反思／覺察／告別／重構／追尋」「以○○的姿態」「以○○的方式」「值得我們深思」「令人深省」「在某種意義上」「歸根究底」「本質上來說」「不可否認」
- **動詞健康訊號**：「她哭了」「他走進廚房」「我聞到咖啡」「醬油乾了一圈」

中文是動詞語言。「她哭了」就是完整的句子。AI 偏愛把哭包進「情緒的流動」這種殼裡，把活的東西變成標本。

## 執行步驟

當使用者貼來一段文字，請依序做下面四件事，全部用繁體中文輸出：

### 第一步：三維度評分

給三個維度各打 0-3 分，並用一句話說明為什麼。評分準則：

- **3 分**：完全沒問題。這個維度像人寫的。
- **2 分**：大致 OK，有少數可以挑剔的地方。
- **1 分**：明顯有 AI 痕跡，影響閱讀感受。
- **0 分**：這個維度全壞，整段都靠這條撐 AI 味。

格式範例：
```
【錨】1 分。整篇沒有任何具體時間、地點、人名，所有事情都發生在「某個午後」。
【歪】2 分。前半節奏 OK，後半連續出現三個對稱排比。
【動】1 分。「對自我的探索」「情感的流動」這類名詞片語塞滿全文。
```

### 第二步：標出最壞的三個句子

從原文裡挑出 AI 味最濃的三個句子，標明它壞在哪個維度（一個句子可能同時壞在多個維度，全部標出來）。

格式範例：
```
1. 「在這個忙碌的城市裡，每個人都在追尋自我的答案。」——錨壞（沒時間沒地點）+ 動壞（「追尋自我的答案」是名詞化）
2. 「她不是在哀悼過去，她是在告別童年。」——歪壞（Not X but Y 對仗句）
3. 「願妳勇敢、願妳溫柔、願妳永遠是自己。」——歪壞（三段排比）+ 動壞（「永遠是自己」太抽象）
```

### 第三步：改寫這三個句子

每個壞掉的句子各改寫一次。改寫後要符合所有三個維度（錨、歪、動）。改寫時注意：

- 不能改變原句要表達的核心意思
- 必須塞入至少一個具體錨點（時間、地點、人名、感官）
- 不能用「不是 X，而是 Y」這類對仗句替換
- 用動詞推，不要用名詞鋪
- 句子長度可以跟原句不一樣，必要時拆成兩三句

如果原句缺的「錨」是只有作者本人才有的（例如他到底發生在哪一天），就在改寫處留 `【補錨：什麼時候？】` 提示作者填，不要瞎編一個假錨點。

### 第四步：一句話總結

最後用一句話告訴使用者：這篇文字最該動的是哪一刀。三個維度裡哪個是主要病灶？建議從哪裡開始改？

範例：
```
這篇主要病在「錨」——通篇都在「某個午後」「某個朋友」的飄詞裡。先把開頭那段抓一個你真實活過的場景塞進去，後面的歪跟動會自動跟著順。
```

## 不要做的事

- **不要把整篇重寫**。只動最壞的三個句子，把改寫權留給作者。AI 味不是用「整篇重寫成另一篇 AI 文」能解決的。
- **不要瞎編錨點**。使用者要的是審查，不是替他編一個假阿芳出來。缺什麼錨就用 `【補錨：⋯⋯】` 留白。
- **不要用三段排比、對仗句、名詞化的句型來寫評分跟總結**。這個 skill 的輸出本身就是規則的示範，自己犯規就沒說服力。
- **不要把寫作用 prompt 跟審查混在一起**。如果使用者要的是「幫我寫」而不是「幫我審查」，就提醒他切換到 stanley-write，不要硬接。

## 進階：搭配寫作流程

如果使用者剛用其他 skill 產出文字（stanley-write、story-telling-rewrite、youtube-summary-slides 的摘要、pdf-summary-slides 的摘要等），這個 skill 適合接在後面跑一次。

但**錨點補不了**——AI 沒有使用者活過的記憶。本 skill 的角色是：標出哪裡缺錨、提示要補什麼錨，至於錨的內容由使用者自己提供。提示時用 `【補錨：什麼時候？哪裡？跟誰？】` 這類問句，引導使用者把記憶補進去。

寫作時自我規範用的 prompt 範本見 `references/writing-prompt.md`，可以給使用者當寫作前的限制條件。
